## 0. 一句话结论

**数据资产是真的（30 万实体、9 个端点全活、CI 连续三天的红已经转绿），
但今天摸底挖出一个比原计划更大的洞：整个语料增长与引用图谱都押在 OpenAlex 一条腿上，
而 OpenAlex 的免费额度是 *本 IP 全网共享的每日美元预算*，实测已被跑光到 `$0`、
`retry-after = 79445 秒`。这不是限流，是上游依赖的单点故障，而且它不会自己恢复。
本轮已修掉 3 个会静默吞掉整轮 CI/整轮抓取的真 bug，并给引用图谱接上了不依赖 key 的第二条源。**

### 1.4 上游依赖：本次摸底挖出的单点故障（P0）

我把 OpenAlex 的 429 响应体完整读了一遍，它说的不是「慢一点」：

```json
{"error":"Rate limit exceeded",
 "message":"Insufficient budget. This request has no API key, so it counts against the
            free daily budget shared by everyone on your network's IP address...",
 "retryAfter":79445, "costUsd":0.0001,
 "dailyRemainingUsd":0, "prepaidRemainingUsd":0, "creditsRemaining":0}
```

- 免费额度 = **共享出口 IP 的每日美元预算**，不是每请求速率限制。
  同出口 IP 的任何其他人跑量，本项目跟着没额度。
- `retryAfter = 79445 秒`（约 22 小时），`dailyRemainingUsd = 0`——退避重试再多次也是同样结果。
- 影响面：**引用图谱**（`pipeline-openalex-citation.js`）与**语料扩库**（`pipeline-openalex-expand.js`）
  两条 pipeline 全部依赖 OpenAlex，今天同时失效。扩库那轮停在 8,927 条。
- 其余候选源实测：

| 源 | 实测结果 | 能否顶上 |
|---|---|---|
| Crossref | `filter=doi:a\|b` 批量 OR **不支持**（`total-results=0`）；单 DOI 直查 `200` 且带 `reference[]`（`10.1016/j.cell.2024.09.022` → 199 条） | **可以**（无 key、无每日预算，只能一 DOI 一请求） |
| Semantic Scholar | `POST /graph/v1/paper/batch` 返回 `429`，需要申请 key | 否（今日不可用） |
| Europe PMC | `DOI:"a" OR DOI:"b"` 命中正常，但覆盖偏生物医学 | 部分（域覆盖不足） |

净结论：**OpenAlex 免费 key 是解锁全量的最短路径**（官方称免费、有独立额度），
但需本人注册；在那之前，Crossref 通路是目前唯一能真实产出跨站引用边的方式。

## 3. 科研方向（四条，每条都挂在本项目**已经存在**的代码/数据上）

### 方向一：跨站引用缺口检测（Cross-site Citation Gap Detection）

**命题**：把引用网络用于**学科能力缺口定位**，而不是文献计量学传统的共引/共词分析。

**已有条件**：260,689 个唯一合法 DOI + 站点归属（30 个站）× 正在抓的引用列表。
`pipeline-openalex-citation.js` 设计上只保留 **source/target 分属不同站点** 的边，
域内引用只计数不算边——这恰好把研究目标收敛到「跨域」，与 30 站跨学科定位天然对齐，
且顺手砍掉 90%+ 的边数（体积可控）。

**方法**：对站对 (A, B) 定义
`gap(A→B) = 引用密度(A→B) × 成熟度差 × 主题距离`，
成熟度用 `cited_by_count` 的 year 分布刻画。留一站点做验证：
被预测「有缺口」的站对，其后续 6 个月是否真的出现了跨站工程/方法成果。

**可发表的点**：现有文献把引用图用于「学科结构发现」或「影响力评估」；
把引用边直接映射成**工程落地缺口**的工作很少，且需要一份跨领域语料——
30 站 × 10k + 全可追溯 DOI 正好就是这份语料。

**当前阻塞**：OpenAlex 额度（见 §1.4）。Crossref 通路可先出小规模结果。

### 方向二：弱监督**特征**可靠性标定（LF Feature Calibration）

**已实现过半**，是本轮之前那轮劳动的直接产物。核心是往上抬一层：
**不去估计 LF 输出标签的可靠性，而去估计 LF 特征本身的可靠性。**

实测支撑（跨样本稳定，非过拟合）：

- `precision agriculture` 在标题出现 943 次，只有 13 篇真被 OpenAlex 指派该概念
  → 逐标签 precision 可测且可跨样本比对（22.5k 标定 / 7.5k 留一：agriculture 0.481→0.375、cancer 0.547→0.489）。
- 标定后只保留 `support≥50 且 precision≥0.2` 的 245 个标签（从 2,200 个），
  整体准确率 **0.061 → 0.375**，`lf_corpus_vocab` 权重升到全场第 2。
- 作用域规则也是实测出来的：只匹配标题 0.0823 > 标题+摘要 0.0598 > 全量 0.0453，
  且标题前 80 字与全标题 precision 完全相同 → 决定「只扫标题前 80 字」。

**可发表的点**：先标定特征、再谈 LF 加权，这条方法论路径在弱监督文献里是空的。
**风险**：这是本项目最扎实、也最不依赖上游配额的一个方向，建议优先级提到第一。

### 方向三：跨域错路由作为语料质量基准（Cross-domain Misrouting Benchmark）

**已有产物**：`export-misroute-review.js` 导出 141,459 个有摘要实体的候选池
（cross-domain 40,160 / mixed 37,298 / cross-cutting 15,809）。
排序键经两轮修正——「跨簇越多越可疑」是错的，跨学科论文才是最典型误报；
正确信号是证据集中在**单一正交簇**。top500 已导出、人工可标注。

**可发表的点**：把「站点主题 ≠ 论文主题」定义成可量化的语料质量指标并做成公开 benchmark，
这类基准在检索/语料治理文献里缺位。

### 方向四（本轮新挖到）：共享出口 IP 下公共学术 API 的配额治理

**这不是从文献里推出来的，是今天踩出来的。** 观测事实：
OpenAlex 免费层按**美元**计价、按**本 IP 全网**共享、每日清零；
同出口的其他用户跑量会让本项目的全部抓取在一天中间突然归零，
且失败形态是「429 + 22 小时后重试」，不是错误也不是超时，日志上只看到「限流」。

对任何依赖公共学术 API 的团队来说，这都是可复现的运维实证：
- **可发表的量**：配额模型（共享 IP + 每日美元预算 + 无 key 降级）的行为特征、
  多源路由与熔断的设计原则（本轮 `pipeline-openalex-citation.js` 里已经落了一版：
  预算耗尽可判定 → 显式 `[ABORT]` → 落游标 → 换源）；
- **可复用的资产**：`--source=openalex|crossref` 的多源路由 + 预算熔断骨架。

**为什么这条算科研方向而不算工程优化**：它回答的是「公共学术基础设施在免费层上
能不能支撑长期自动化采集」——一个有真实受众的问题，而且我们手上有第一手响应体。

## 4. 硬骨头（攻克路径与代价，按 ROI 排序）

### A. 全量语义检索在 Workers 上是架构级不可行 —— 已量化，别再调参数

| 方案 | 体积 | 结论 |
|---|---|---|
| 单文件全量 300k 带摘要 | **≈ 150 MB** | Worker 内存 128MB，`JSON.parse` 直接 OOM |
| 当前单文件 18k（top-600/站） | 10.82 MB | 覆盖率 6%，已接近单文件安全上限 |
| 全量按站分片 | **149.28 MB（30 片 / 300k）** | 体积可行，但需要加载器 |

**攻克路径**：① 分片产物已能生成（`--shards`）但**必须先有消费方才落盘**，否则白占 Pages 配额；
② 分片托管到 **jsDelivr**（免费 CDN、不吃 Pages 配额、单文件 5MB 远低于其 20MB 限制，
本项目公开仓库天然可 CDN 化），Worker 按 `sites` 参数按需加载 + 时间预算渐进加载；
③ 重写 `api-guard/worker.js` 的索引加载函数（约 60 行），
**任何失败都回退到现有单文件索引**——不要让「优雅降级」变成生产静默故障；
④ 更彻底的是迁到向量库（pgvector 等），代价是引入运维与成本。

**本轮不做**：无消费方 + 要重部署 CF 生产，风险收益比不成立。体积已量化，随时可接。

### B. 引用图谱（进行中，今天新增一条熔断路径）

- 已跑通：260,689 个 DOI → 5,214 批批量查询验证可行；摘要（`abstract_inverted_index`）顺带回填。
- 体积预算：OpenAlex 原始 payload ≈4KB/条 × 260k ≈ 1GB，**绝不可落库**，
  只落 id 映射 + 引用计数 + 跨站边（每实体限 12 条）。
- 新状态：OpenAlex 额度耗尽时自动 `[ABORT]` 并保留已完成部分；Crossref 通路（`--source=crossref`）可独立产出边。
- 还没到的那一步：把跨站边**落成数据集并给消费方**（当前只出 POC 报告），
  以及做「引用缺口分数」的可视化/API 出口。

### C. 语料增长已停滞 + 上游单腿支撑

30 站 × 10,000 已满容、摘要回填缺口 0、每小时新增 0；而 OpenAlex 扩库今天额度归零。
**扩库方案必须改为多源**：Crossref（可查 reference 与元数据，无每日预算）作为主力，
Europe PMC 补生物医学域，OpenAlex 有 key 时作批量加速。
这是把「一条腿走路」换成「三条腿」的实际工程活，也是 §3 方向四要研究的东西。

## 5. 市场壁垒（诚实评估）

### 5.1 现在**不算**壁垒的东西

- **数据量**：30 万实体听起来大，源是 OpenAlex/Crossref/GitHub 等开放 API，任何人都能抓一份。
  **复制成本 ≈ 0**，不构成壁垒。
- **「我们有 30 个站」**：站点是内容编排，不是资产。
- **语义检索**：覆盖率 6%，短期不是卖点。
- **引用图谱（还没建成）**：一旦建成是真壁垒，但**现在还没有**，别对外当卖点讲。

### 5.2 真正能构成壁垒的四件事

1. **跨域整合视图**（唯一可持续的差异化）
   单域检索谁都能做；把 30 个学科的引文流织成一张图并持续维护 schema 一致性，需要持续运维投入。
   今天修的护栏自锁 bug 就是这类资产的具体形态——**别人重新搭一遍会踩一模一样的坑**：
   多写入者 + 跨 schema 基线 + 护栏自锁。这类「踩过的坑本身」无法被一次 `git clone` 复制，
   只能在长期运维中累积。

2. **可追溯的结构化输出**（ToB 付钱的理由）
   每条实体带 DOI / URL / 来源站 / `publishedDate` / `confidence`，外部可独立核验。
   对做 RAG 的团队，这是「能作为 grounding 源」与「只能当灵感参考」的区别。

3. **运维正确性**（稳定性即卖点）
   CI 门禁前移到编译期、护栏基线隔离、ETL 幂等、部署后回读校验（本轮换的 `deploy-api.mjs` 就是）。
   消费者接的是生产数据，**一天静默吐错数据比一天挂掉更致命**。

4. **上游冗余与熔断**（本轮新增）
   当同出口 IP 的其他人把你依赖的免费额度跑光时，你还有 Crossref 兜底、
   有预算可判定、有游标能续跑、有 POC 诊断。这个「不自知地停在半夜」的坑，
   踩过一次就不会再踩。

### 5.3 当前最大的缺口（比数据还大）

**有数据、没商业闭环。** 具体：

- API 端点 9 个全活，但消费者无法自助接入——`openapi.yaml` 与 `docs/consumer-onboarding.md`
  此前在仓库里根本不存在（本轮已补并推送）。
- 定价页只在构建产物 `_site/pricing.html`，**没有对外可结算路径**。
- 3 个学术端点 + 1 个引用边端点 404 会直接劝退首批 TA 型用户（本轮实测已定位：
  数据层 4/4 已上线，断的是 Worker 脚本部署链，见 §2-24）。
- 摘要已填满、实体已满容，**数据侧再投入 ROI 低**，投入该转向「让消费者用起来」。

**建议下一步排序**：
① 拿 OpenAlex 免费 key（解锁引用图谱 + 扩库）→ ② 救活 3 个学术端点
→ ③ 把 onboarding 文档推到对外域 → ④ 定价页与支付闭环落地
→ ⑤ 引用图谱产出后，把它做成 Pro 档第一杀手锏（「跨站引用缺口」不是任何单域平台能给的）。
