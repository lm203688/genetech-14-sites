## 4. Phase 3 — 计算化验证（无需人类专家，2–3 周，替代原人类验证）

> **路线变更说明**：人类专家招募不可行。以下三套互补的**离线/自动验证**是方法/数据类论文认可的等效替代（审稿人接受"可复现的回溯验证 + 已知金标准复现"作为方法有效性证据）。`tools/sample-hypotheses.mjs` 与 `tools/aggregate-review.mjs` 仍保留，若未来能招募专家可直接复用，但**当前不作为投稿阻塞项**。

### T3.1 回溯验证（已落地 `tools/validate-hypotheses-retro.mjs`，离线、无需外网）
- **原理（Swanson 式 retrospective）**：以 T0 切分，只用 `publishedDate < T0` 的引用边定义"历史状态"；候选桥 = 两域"共享主题但历史零引用"的域对（完全复刻假设卡生成规则）；验证同一域对在 T0 之后是否真出现引用 → "涌现命中"。
- **执行**：`node tools/validate-hypotheses-retro.mjs --t0=2023-01-01`（建议跑 2021/2022/2023 三个切点取稳健区间）。
- **首跑实测（T0=2023）**：候选桥 592、涌现 419（**70.8%**）、随机对涌现率 79.3%、**lift 0.89**、跳过无年份边 5758。
- **诚实解读与必改项（论文前必须做）**：首跑 lift 0.89 < 1，说明"原始涌现"不是强预测信号（多数域对随时间都会互引）。改进：① 验证口径从"域对是否出现任何后向引用"收紧为"是否在**特定共享主题 T**上后出现引用"（这才是假设卡的真实含义）；② 改报 precision@k 与"非显然桥"占比；③ 论文中如实报告 lift 并讨论局限（方法/数据论文允许，关键是透明）。
- **完成判据**：产出 `reports/retro-validation-<T0>.json`；论文"Validation"节含 3 切点曲线 + 与随机基线对比 + 局限讨论。

### T3.2 已知发现复现基准（已落地 `tools/benchmark-known-discoveries.mjs` + `data/known-discoveries.json`）
- **原理**：取 15 条历史上已证实的跨域发现（映射到本项目 30 域），检验方法在历史切点是否会把 (A,B,主题) 判为低引用桥接候选且随后真涌现。ML/IR 标准的"已知金标准复现"。
- **执行**：`node tools/benchmark-known-discoveries.mjs --t0=2023-01-01`
- **首跑实测**：recall **33.3%**（5/15 命中）。漏检主因：相关主题未进本项目 tag 词表，或该对已有引用。
- **完成判据**：recall 报告入论文；将 `known-discoveries.json` 扩充到 ≥30 条提升统计稳健性；对漏检项做误差分析。

### T3.3 独立语料确认（合并原 P4；若用户能申请 OpenAlex key）
- 对 top-N 假设卡查 OpenAlex works API 确认跨域桥接是否已存在 → 量化"零引用对假阴性率"。
- **若用户也无法申请 key**：改用 Crossref/PMC 免 key 接口，或仅以 T3.1/T3.2 作主验证（已足够支撑方法/数据论文）。

### T3.4 原抽样/聚合脚本降为"可选补充"
- `tools/sample-hypotheses.mjs` + `tools/aggregate-review.mjs` 保留：未来若能招募专家直接复用；当前不阻塞投稿。
