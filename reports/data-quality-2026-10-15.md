## 二、关键发现：缺失 abstract 无法回填

### 2.1 问题规模

- **90,926 条实体缺失 abstract**（30.89%）
- 其中 **87,695 条有 DOI**（可从学术 API 回填）
- 影响：Pagefind 搜索质量、语义向量化、引用完整性

### 2.2 回填尝试结果

测试三个主要学术 API 的 abstract 覆盖率（neuromorphic 站 20 个 DOI 样本）：

| API | 覆盖率 | 失败原因 |
|---|---|---|
| Crossref | **0/20 (0%)** | API 返回 200 但 `abstract` 字段为空 |
| OpenAlex | **0/20 (0%)** | API 返回 404（DOI 未收录） |
| Semantic Scholar | **0/20 (0%)** | 首个返回空 abstract，后续 429 限流 |

### 2.3 根因分析

**为什么无法回填？**

1. **DOI 太新**：这些是 2025-2026 年的论文/预印本，学术索引尚未收录
2. **出版类型**：主要是会议论文、预印本（SSRN）、书籍章节，学术 API 主要收录期刊论文
3. **数据源限制**：Crossref 本身就没有 abstract（元数据不完整）

### 2.4 影响评估

| 影响领域 | 严重程度 | 说明 |
|---|---|---|
| Pagefind 搜索 | 中 | 无 abstract 的实体只能搜标题，召回率低 |
| 语义向量化 | 高 | 无 abstract 无法生成有效向量 |
| 引用完整性 | 低 | 引用格式（BibTeX/APA）不依赖 abstract |
| 用户浏览 | 低 | 用户主要看标题/作者/DOI |

## 四、建议方案

### 4.1 短期（可立即执行）

1. **接受限制**：30.89% 缺失 abstract 是数据源限制，非工程问题
2. **优化搜索**：Pagefind 已可工作（搜标题即可），无需阻塞
3. **文档标注**：在实体详情页标注"摘要待补充"

### 4.2 中期（1-2 周）

1. **补充数据源**：从 PubMed、arXiv 直接抓取（非 DOI 查询）
2. **LLM 生成**：对无 abstract 的实体，用 LLM 从标题/标签生成简短摘要
3. **用户贡献**：开放 API 允许用户补充 abstract（类似 Wikidata 模式）

### 4.3 长期（1 个月+）

1. **出版社合作**：与 Elsevier/IEEE/Springer 合作获取完整元数据
2. **自建索引**：部署 PubMed Central、arXiv 镜像，实时同步
3. **开放获取**：优先收录 OA 论文（abstract 完整率高）

## 五、结论

**数据质量整体良好**（DOI 覆盖 87%、URL 100%、无重复），但 **abstract 缺失 30.89% 是硬性瓶颈**，短期无法通过 API 回填解决。

**建议**：接受当前限制，优先推进其他工作（Pagefind 搜索已可工作，不依赖 abstract）。abstract 回填作为长期优化项。
