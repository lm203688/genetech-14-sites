## 1. mcp-server（分发核心 · 全仓最健康）

- **功能清单**：stdio + streamable HTTP 双模式；14 个本地工具（`src/index.mjs`）：list_sites / query_entities / get_entity / semantic_search（BM25+字段加权+RRF）/ graph_search / export_citation（BibTeX/APA/RIS）/ citation_gaps / ask（LLM 桥接）/ submit_request / retrieve_requests / intake_health / verify_entity / snapshot_at / domain_relatedness。
- **流程走查**：`npm install && node src/index.mjs`，本机实测 initialize/tools/list/tools/call 全通，citation_gaps 返回真实数据（30 站/870 有向对/140 零引用对）。10-13 修复后首调延迟 579ms、CI 门禁在。**断裂点：npm 上 `@genetech/data-mcp` 最新 1.1.0，本地已 2.0.0——README 宣称的 `npx -y @genetech/data-mcp` 零安装路径拿到的是旧工具集（少了 verify_entity/snapshot_at/domain_relatedness 及全部 10-13 修复）**；14 个工具中 3 个新工具无任何文档。
- **完整性**：88。主干真实可用；向量检索仍需自配 GENETECH_EMBED_URL；ask 未配 LLM 时退化为实体列表。
- **人类使用习惯**：README 有 30 秒上手 + Claude Desktop 配置 + Python 示例，接入 <10 分钟。扣分：TS 示例语法写给 Python 用户、工具表只列 11 个。
- **竞品对标**：Semantic Scholar MCP（官方）、Scite MCP（已进主流客户端）全部**免 key 检索**；GeneTech 核心检索要 key。且响应全塞 text JSON、无分页 cursor。
- **可融合开源技术**：`@modelcontextprotocol/sdk` 自带的 Inspector 测试链；**Speakeasy/Stainless** 从根目录已有 `openapi.yaml` 生成 SDK 与文档，消灭 README 手写漂移；**LangChain MCP adapters** 替换自研 llm-bridge。
- **评分**：完整性 88 / 可用性 80 / 竞争差距 55。
- **提升方案**：① 立即 publish 2.0.0（否则"零安装"是假承诺）；② 补 3 个工具的文档与 examples；③ 补分页 cursor 与结构化 content（output schema）。

## 2. mcp-remote（远程分发 · 壳完整管道断）

- **功能清单**：Cloudflare Worker（`worker.js` 209 行声明 14 工具 schema）转发上游 `api.swarmlabs.tools`；/health /manifest /mcp 三路由；Free 限流（KV 计数）+ Bearer 校验。
- **流程走查**：按 README 接入 10 分钟能连上——但连上后 **11/14 工具报错**：`/v1/entities/pmid-1` 404、`/v1/ask` 404、`/v1/citation/relatedness` 404、`/v1/domains/{site}/snapshot` 落到 Pages 错页、semantic_search 用 GET 401（上游只收 POST）、submit_request spec 对象丢失。只有 list_sites / citation_gaps / intake_health 三个通。**静默失败：未配 LICENSE_VALIDATE_URL 时返回 `pro-unverified` 直接放行——任何假 Bearer 都是 Pro。** GET /mcp 返回空 SSE，客户端挂起。
- **完整性**：35。上游路由表与真实 API 系统性错位，且 schema 与本地版漂移（remote 用 topK、本地用 limit）。
- **人类使用习惯**：README 是部署手册级（curl 验证、Claude/Cursor 配置、成本表俱全），但工具 404 无错误码文档。
- **竞品对标**：Cloudflare 官方 `workers-mcp` 模板（OAuth + 真实 SSE + Durable Object 会话）三件套齐备；这里是手写壳。
- **可融合开源技术**：`cloudflare/workers-mcp`（整体替换传输层）；**Unkey**（替换 KV 手写限流与 GUX_ 自研 key 体系）；**Hono + @hono/mcp** 替代裸 switch 网关。
- **评分**：完整性 35 / 可用性 45 / 竞争差距 30。
- **提升方案**：① 用 CI 契约测试：14 工具逐一 tools/call 断言；② 修 GET/POST 方法错配与 schema 漂移（与本地共用一份 schema 定义）；③ fail-closed：未配 LICENSE_VALIDATE_URL 时拒 Pro 而非 `pro-unverified`；④ 上架前以官方模板重写 SSE 会话。

## 3. api-guard（API 网关 · 鉴权真、token 乱）

- **功能清单**：Worker（1705 行）：免费层静态 JSON 限流转发；Pro 层 `/api/pro/*` + `/v1/search/*` 的 `gtk_` HMAC-SHA256 无状态 key 校验；`/v1/intel/*` 情报 API（apply/demand/consumer/admin，ckn_+gtk_ 双 key）；域路径映射 Pages 静态文件；`/api/llm/*` OpenAI 兼容桥接。
- **流程走查**：注册→genkey 签发 gtk_→Bearer 调 `/v1/search/semantic`（POST，实测无 key 401，fail-closed 正确）。**断裂点：三套 key 体系并存——api-guard 用 `gtk_`、mcp-remote README 说 `GUX_`、payment-template 发随机 `gtk_`（非 HMAC，api-guard 校验不了）**；`/v1/entities` 的 site/offset/q 参数全部无效；免费层限流是 per-isolate 内存 Map（多 isolate 下限流产同虚设）。安全隐患：admin key 明文 fallback 硬编码在源码。
- **完整性**：62。
- **人类使用习惯**：48 行 README 讲清策略，但无部署 URL 的 API 文档、无错误码表（401/403/429 语义只在代码 message 里）。
- **竞品对标**：RapidAPI/Kong 的 key 签发+配额+分析全套；OpenAlex 免 key 开放。差距：无 key 管理后台、无 usage 统计。
- **可融合开源技术**：**Unkey**（统一三套 token 为完整 key 生命周期）；Cloudflare rate-limiting binding（Durable Object 全局限流）。
- **评分**：完整性 62 / 可用性 55 / 竞争差距 40。
- **提升方案**：① 删除 admin key 硬编码 fallback（改 secret 绑定）；② token 体系统一（Unkey 或按站 HMAC 一种）；③ 开放 `/v1/entities` 过滤参数；④ 全局限流 + 公开错误码表。

- **评分**：完整性 55 / 可用性 45 / 竞争差距 45。
- **提升方案**：① 修 TS 双请求（一行）；② README 全部示例改为对代码跑通的形式；③ openapi.yaml 唯一真源 + 生成 SDK；④ npm/PyPI 分发。

- **评分**：完整性 80 / 可用性 55 / 竞争差距 45。

## 7. operations-plan（数据流水线 · 工程纪律最好，方法层最旧）

- **功能清单**：56 个脚本 / 16,697 行，全链真实：采集（OpenAlex 游标断点续抓、Crossref+EuropePMC 免密钥兜底、11 源回填）→ 解析（refs→跨站边、被引回填 48,760）→ 分析（ER / 立场 / 标签编程 / 质量门 / 缺口矩阵）→ 发布（sync-live / self-db-build / closed-loop-engine 7 阶段真实编排）→ 运维（scheduler-v2 / 飞轮停滞监控）。
- **流程走查**：新论文实体路径完整可追。**断点：① OpenAlex 共享 IP 日预算 429 打满，log 停在 12.7%；② 被引侧 96.2% 不在库；③ CF Pages ~99% 容量把 label --write 与扩库闸死；④ 实体级 lastUpdated 全部停留 2026-08-31~09-01（约 6 周）——内容陈旧是当前最大隐性风险。**
- **ACTUAL 算法**（方法层关键）：ER = Jaccard≥0.7 + Levenshtein≥0.8 + union-find（代码注释明确否决 Splink：duckdb wheel 下载超时）；立场 = 词典加权计数（W_NEG=1.15，±0.15 阈值）；检索 = BM25(1.5,0.75)+字段加权+RRF，向量 env 门控默认关；标签编程 = Snorkel 式 LF+LabelModel（实测线上 LF precision≈0.06，弱）。
- **人类使用习惯**：每个脚本头部注释极佳（"为什么存在/为何不用 X"决策日志），30 分钟可跑通；扣分：logs/ 停更 10-04、cron 分散 4 个 workflow 双轨。
- **竞品对标**：OpenAlex = 实体级全量 API+权威 ID 概率归并；S2ORC = SciBERT 全文结构化；Scite = citation-statement 分类模型。**差距是方法代差：字符串相似 vs 概率链接，词典 vs 意图分类模型，无向量 vs embedding。**
- **可融合开源技术**：**Splink**（概率记录链接，直接给 match probability）；**BAAI/bge-m3 + HuggingFace TEI**（解 tags-inverse Recall 6.5% 塌方）；**distilabel**（LF→LLM 合成标签升级 LabelModel）；**SciCite BERT**（替代立场词典）。
- **评分**：完整性 70 / 先进性 52 / 竞争差距 45。
- **提升方案**：① 换自托管 OpenAlex（或 EuropePMC 为主源）解 429；② JSON→DuckDB/Parquet 解容量闸；③ TEI 自托管向量 + 混合检索；④ Splink 换 Jaccard。

## 9. eval（评测 · 循环基准已修，覆盖面不足）

- **功能清单**：`generate-queries.mjs`（v2 基准，seed=20261013 固定，4 类构造 A/B/C/D，300 条，sha256 指纹）+ `run-eval.mjs`（Recall@10/MRR/NDCG@10 + byType/perSite 分解 + leaderboard HTML）。
- **流程走查**：本轮实跑 5.53s 确定性复现：**Recall@10=0.4126、MRR=0.3724、NDCG=0.3646、15/30 完全未召回、tags-inverse 类 0.065**。10-13 报告的 N3（query 抄答案 Recall 恒 100%）**已修复**——查询与答案已不同源，方法论诚实度高于多数同类。**当前断点：默认只跑 3/30 站**（`run-eval.mjs` slice(0,3)），90% 站点零度量；无延迟/并发测量。
- **人类使用习惯**：60。leaderboard 有方法论披露区；但默认 3 站这个坑没有任何提示。
- **竞品对标**：BEIR/MTEB 标准。差距：无跨模型横评、无分层采样。
- **可融合开源技术**：`ir_measures`/`pytrec_eval` 指标库；MTEB 式多模型横评框架。
- **评分**：完整性 68 / 先进性 60 / 竞争差距 45。

## 11. 30 站网站层（访客触点 · 数据浏览器而非产品）

- **功能清单**：30 站目录只含 `website/api/{index,entities}.json` 数据契约；真正的站由 `tools/build-site.mjs`（2612 行）CI 生成到 `_site/`：每站列表页+topic 页+全局 search/ask/graph/mcp/data/insights/license/blog 页 + `api/{graph,authors,timeline,stats}.json`。
- **流程走查**：实体入站→等下一次构建才出页面；push 触发曾漏建（有 4h 兜底 cron 补丁）；**无 per-entity 详情页**——实体只以列表卡片存在，没有 `entity/<id>.html`，因此不能被外链、不能被 Google 单篇收录、无法做 citation backlink。
- **完整性**：62。无 TODO/lorem；但每个 `index.json` 的 totalEntities 均写死 10000，与实际 9,416–9,974 系统性漂移。
- **人类使用习惯（访客视角）**：48。**搜索是硬伤**：站点内搜索 lazy fetch 整站 entities.json（9–14MB）做 `indexOf` 子串匹配，无分词；全局 search.html 跨 30 站等于拉数百 MB。ask.html 依赖外部 Worker，Worker 挂问答即死。有 viewport + 基础响应式；引用展示有（source chip、置信度、DOI 外链）但无引用关系可视化。
- **竞品对标**：Elicit/Connected Papers/Litmaps/Scite 的共同形态：**每篇论文一个详情页+引用图谱入口+facet 筛选**。本项目连一个实体详情 URL 都没有。用户体验差距是本项目与国际竞品**最大**的单项差距。
- **可融合开源技术**：**Pagefind**（Rust 静态索引，build 后几十 KB 分片，零后端，支持中文，直接替换整包 JSON 下拉）；**Astro + content collections**（294K 实体 per-entity 详情页+SEO 收录）；D3/cosmograph 做 per-entity 引用子图（数据已在 api/graph.json）。
- **评分**：完整性 62 / 可用性 48 / 竞争差距 35。
- **提升方案**：① Pagefind 换搜索（半天，收益最大）；② Astro 生成实体详情页（1-2 周，改变产品性质）；③ 修 index.json 计数漂移。

## 15. 横向结论：五个系统性模式

1. **"声明完成"与"实测可用"的系统性落差**。14 个板块里 9 个的 README 强于其代码现状：npm 1.1.0 vs 本地 2.0.0、mcp-remote 14 工具 11 个 404、SDK README 示例全部失效、README 锚点指向 stub。**同一个病根：单一承诺没有自动化测试背书。** 已修好的三处（N1/N2/N3）共同点是都补了 CI 门禁——验证了"门禁驱动真实"这条路在本项目有效。
2. **三套 key / 两套支付 / 双轨调度**。api-guard（gtk_ HMAC）/ mcp-remote（GUX_）/ payment-template（随机 gtk_）互不兼容；虎皮椒与 Creem 两条支付链共用"手动 wrangler deploy"人工门；cron 散落 4 个 workflow 与本地 scheduler 双轨。**这是典型的"引擎优先"特征：每个板块各自最优，系统层没有收敛。**
3. **护城河资产在真做，命脉板块同时带伤**。数据层（294,330 实体 / 99,725 节点 KG / 25,682 引用边 / 护栏 / 可复现评测）= 差异化来源；但分发（mcp-remote 断）+ 变现（轮询 404 / license 送达断）+ 触点（无详情页 / 搜索拉整包 JSON）= 三个出口全部半开。**国际竞品（Scite/Elicit）的形态是反的：出口成熟、上游免费。**
4. **工程纪律高、科学方法旧**。56 脚本的注释质量、guard 的失效-修复闭环、leaderboard 的方法论披露都超过一般开源项目；但加工层三个核心仍是 Jaccard / 词典 / BM25，直接对标就是 OpenAlex（概率归并）+ Scite（意图分类模型）+ BEIR 标准向量检索——**这是 10-12 报告"科学先进性 35 分"在板块级的逐项证实。**
5. **飞轮停滞是所有板块共同的上游约束**。实体 lastUpdated 46 天不动（state cursor 停 09-02）、KV 0 keys（零售出）、data-requests 零请求、audit 6 行——四个"零"指向同一件事：**系统已建成但未运转**。修板块不如先让飞轮转起来。
