## 5. 技术壁垒的真相（本报告核心章节）

### 5.1 当前"壁垒"的真实构成

项目对外叙事里的壁垒是：**跨源归一 + 跨域桥接 + 中文政产学融合**。逐条实测：

| 声称的壁垒 | 实测 | 结论 |
|---|---|---|
| **跨源归一** | `dedupeKey` = 有 DOI 用 `doi:`，无 DOI 用 `标题#作者`。这只在**站内**去重，且真重复率 0.00%——说明**跨源记录几乎不重叠**，归一"没什么可做"。真正的跨源实体解析（同一篇论文在 OpenAlex/Crossref/PubMed 的不同 ID 合并）**未实现** | ❌ **未落地** |
| **跨域桥接** | 28,001 条引用边中 93% 来自 legacy merge；由当前管道解析出的仅 1,961 条 | ❌ **基座过薄** |
| **中文政产学融合** | 实体来源全部是英文源（crossref/openalex/europepmc/datacite/pubmed/arxiv/preprints）；无 CNKI/万方/CSCD | ❌ **未落地** |

> **这是本报告最重要的结论**：项目最核心的三个差异化宣称，**两个完全未实现，一个建立在一个 1,634 条记录的基座上**。而"1,634 条记录产出 1,961 条库内引用边"这个数字，直接说明**引用网络的覆盖是 <1% 量级**——59,623 条声明里 50,686 条是同站自引被跳过，真正跨域的、能被解析的只有不到 2 千条。

### 5.2 为什么"缺口发现"目前不能当卖点

`citation_gaps` 工具（v1.2.0）是本项目最具原创性的功能。但它的结论建立在 28,001 条边上，而其中：

```
59,623 条引用声明
  ├─ 50,686 条同站自引 → 跳过（85%）
  ├─  1,961 条跨站且被引文档在库 → 成为边（3.3%）
  └─  7,171 条跨站但被引文档不在库 → 未解析（12%）
+ 26,044 条 legacy merge（来源不明）
= 28,001 条"跨域引用边"
```

**后果**：
1. **101 个"零引用域对"里，很大比例是"我们没抓到"而非"没人研究"**。项目自己的代码就写了这句警告（`interpretation` 字段），说明作者意识到了问题——但这句警告不能替代数据。
2. 若把这份缺口报告当作对外产品（如 B4 的月度《跨域研究空白报告》），**一旦被领域专家抽检，可信度会崩塌**。这恰恰是项目最珍视的"可被第三方复核"属性的反面。

**结论**：缺口发现**方向极对、数据极薄**。它需要的不是"再包装"，而是**先把引用网络从 1,634 条种子扩到万级**（见 §8 Tier 1）。

### 5.3 什么才是真壁垒（定义）

| 壁垒类型 | 特征 | 本项目现状 |
|---|---|---|
| **算法壁垒** | 别人复现不出同等效果（如立场分类 F1） | ❌ 无 |
| **数据飞轮壁垒** | 用的人越多数据越好，形成正反馈 | 🟡 有设想，未转动 |
| **标准话语权** | 你的 schema/评测成为行业基准 | ❌ 无 |
| **切换成本** | 客户已深度集成，迁移代价高 | ❌ 无（API 可替换） |
| **合规壁垒** | 独家授权 / 牌照 | ❌ 无 |
| **流程壁垒** | 复杂但可复刻 | ✅ **只有这个** |

**必须清醒**：流程壁垒（护栏、审计、编排）是**必要但不充分**的。它让系统"不出错"，但不能让系统"不可替代"。真正的护城河只能来自上表前三行——**算法、飞轮、标准**。

## 6. 2026 技术前沿与市场需求（外部对标）

### 6.1 协议层：MCP 2026-07-28（项目必须跟上）

2026-07-28 是 MCP 诞生以来最大重构（已官方发布）：

- **无状态核心**：移除 `initialize` 握手与 `Mcp-Session-Id`，改**每请求自包含** + per-request 能力协商
- **强制头校验**：Streamable HTTP 要求 `Mcp-Method` / `Mcp-Name`，头体不一致必须拒绝
- **多轮往返**：`InputRequiredResult` 取代长连接 SSE 推送
- **Extensions 体系**：`Tasks`（异步长任务）、`Skills over MCP`、`MCP Apps`（会话内交互 UI）
- **错误码**：资源未找到 `-32002` → `-32602`
- **官方 SDK 已切 v2 新包**

**对项目的含义**：MCP 是本项目**最重要的对外分发通道**，而它停在 v1 线、仅 stdio、未发布。竞品 **Scite 已在 2026 Q3 发布官方 MCP server 并进入官方 registry**——"知识底座 MCP 化"的窗口正在被占。

### 6.2 检索层：GraphRAG / Agentic RAG 已成标配

2026 的检索前沿是**"领域路由 → 向量召回 → 图扩展 → cross-encoder 重排"四段式**，即 GraphRAG + Agentic RAG 融合。自托管 embedding（bge-m3 / Qwen3-Embedding / Jina v4）+ TEI 服务 + HNSW 已是成熟开源方案。

**对项目的含义**：项目目前是 **BM25 + 字段加权 + RRF** 的 token 匹配，**落后一代**。而 P3 原则（不自租模型）**完全不妨碍**自托管开源 embedding——把"不自租模型"误读成"不做向量"，是本项目一次方向性的自我设限。

### 6.3 市场层：数据授权是真实成交市场

| 事实（2026） | 含义 |
|---|---|
| Anthropic 作者和解 $15 亿（约 $3,000/本） | 责任锚在**获取方式**，provenance 成采购刚需 |
| Wiley × AI 实验室、Taylor & Francis × Microsoft（$10M+） | **学术数据授权有公开成交先例** |
| 2026 惯例：2-5 年、**训练权 + 实时 feed 打包**、**归因条款化** | 我们的 API/MCP 就是"实时 feed"，应与训练权打包谈 |
| 双边协议单条价是市场价 **2-10×** | 别只做自助买断，**要做 BD** |

**对项目的含义**：方向正确，缺的是**把资产翻译成买家语言**——而"翻译"的前提是**资产本身够硬**（这正是 §5 的短板）。

### 6.4 竞品层：坐标已经清晰

## 9. 生态发展建议

### 9.1 分发：MCP 是主战场

- **迁 v2 + 发布 + remote 端点**：`npx` 只是入门，企业要 **URL + key**（复用 api-guard HMAC）
- **进官方 registry + Glama + Smithery**（`glama.json` 已备）
- **利用 2026-07-28 新特性**：`Tasks` 扩展做长任务（如批量导出）、`MCP Apps` 做会话内可视化

### 9.2 开源：开引擎、不开数据

- **开源加工引擎**（ER / stance / 检索 / 评测代码），数据产物保持授权——**引擎开源 = 标准话语权的起点**
- 社区可贡献：新域适配器、新源连接器、评测集
- 参考：Scite 靠 MCP 进 registry 建立"引用感知数据层"心智，我们应靠**开源引擎 + 公开评测**建立"可验证证据层"心智

### 9.3 让"对外数字"自动化（治 M4 的根）

**问题**：本轮又发现 3 处对外口径偏离（4.9 万 / 14 站 / 22 域）。**人工维护的文案必然漂移**。

**解法**：
- 所有对外数字由脚本从 `data/` 实时生成，写入 `README` / `ai.txt` / 站点 / BD 物料
- 进 CI：数字与产物不一致 → 门禁变红（复用 `pipeline-domain-claim-guard.js` 的模式）
- 对外文档只发白名单，其余由 `docs-visibility.policy.json` 机器判定

### 9.4 结盟：与 OA 基础设施互补而非竞争

OpenAlex / Crossref / Europe PMC / CORE / unpaywall / Retraction Watch / Software Heritage——**它们是源，我们是加工层**。主动成为它们的下游增值层，而非试图取代。

### 9.5 中文生态（兑现"政产学融合"）

- 对接 CNKI / 万方 / CSCD（元数据 + 摘要，注意授权）
- 中文 embedding（Qwen3-Embedding / bge-m3 中文能力）
- 对接"可信数据空间"试点 + 数据资产入表通道
