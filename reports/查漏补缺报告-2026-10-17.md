## 0. 核心目标（查漏补缺的对标基准）

来自 `ai.txt` + `README.md` 的项目自我定位：

- **一句话**：面向 AI 的跨源、跨域科研知识引擎，覆盖 **30 个垂直科学域**，每条实体带 DOI/PMID + 上游 provenance，可被第三方独立复核。
- **主张的差异化能力**（README §能力声明与事实边界）：跨源实体解析、引用立场抽取、向量检索、跨源归一、中文政产学融合——但 README **自承这五项截至 2026-10-10 "未实现 / 无 / 未落地"**。
- **主张的差异化基座**：可验证科学证据图谱（Verifiable Scientific Evidence Graph）、时间机器溯源、Guard 矩阵、6-Agent 闭环、数据飞轮。
- **对外承诺规模**（README/ai.txt 自引）：294,330 实体、30 站、KG 36,107 节点 / 99,725 边、MCP 工具若干。

**查漏补缺的判据**：上述每一条"主张"，要么有物化产物支撑，要么就是缺口。

## 3. 分类详述

### 3.1 数据地基缺口（G5/G6/G7/G8/G9）

- **G5 Parquet 未铺开**：`data/parquet/` 目录里只有 `_neuromorphic.json`（11MB）与 `_neuromorphic.sql`（865B）。其余 29 站仍靠 `website/api/entities.json`（单站 11.7–21.2MB，全量 ~518MB）做主载体。round9 的 F9（DuckDB/Parquet 转正，目标冷启动 <200ms）**仅做了 neuromorphic 一个站点的 PoC**，离"30 站转正"差 29 站。影响：加载 579ms 靠分片勉强压住，一旦上向量/claim 层成本会失控。
- **G6 claim 层 ID 时序风险**：`hypothesis-cards.json`（940 卡，含 `litellbridge/sparse_bridge_v2/...` 多类型）、`claims.json`、`extracted-claims.json` 生成于 10-16，而 `identity-map.json` 生成于 10-17 02:09——**claim/假设层跑在 ID 规范化之前**。好消息：假设卡本体用 `id: HYP-...` + **站点名**（robot-parts / low-altitude）作引用，不直接绑原始实体 ID，重映射风险被部分隔离；但 `claims.json`/`extracted-claims.json` 若按 `doi:/oa:/裸 ID` 引用实体，F5 之后需对 claim 层做一轮 remap，否则"假设↔实体"链路会在 ID 归一后断裂。
- **G7 原子写残留**：`data/identity-map.json.tmp.56044.cfa6b853` 是 0 字节的残留临时文件，说明 `atomic-write.cjs` 在异常/中断路径没有清理 tmp。这本身就是 F3 要解决的"写一半崩溃留半截"的同源问题，需补 finally 清理。
- **G8 非科学目录混入**：30 站里 `agent-ecosystem` 是"智能体生态"目录，不是科学域；KG 的 `stations=56` 还含 `docs/data/guards/tmp` 等 infra 目录。README 主张"30 个垂直科研域"，实际计数里混入了 ≥1 个非科学目录，跨域发现/缺口腔号会带基础设施噪声。
- **G9 数据时效**：所有 30 站实体 `updatedAt` 停在 2026-08-31，飞轮约 45 天未转。10-16/17 新建的 claims/hypothesis/KG/identity-map 全部基于这批陈旧实体——**衍生产物很新，但原料是 45 天前的**。外部感知是"停更"。

### 3.2 服务与对外口径缺口（G1/G2/G3/G4/G12）

- **G1 glama.json 严重滞后**：`glama.json`（根，即 Glama/SMITHERY 对外目录源）displayName 写"**14 站**前沿科技知识库 MCP"，description 写"14 vertical domains"，capabilities.tools **只列 5 个**（list_sites/query_entities/get_entity/semantic_search/export_citation）。而实测 30 站、14 工具。任何看 Glama 目录的 agent 只会拿到 5 工具 + 错误站数。**这是对外可信度的最直接漏点**。修复：把 mcp-server/README 里准确的 14 工具清单 + 30 站抄进 glama.json（注意 mcp-server/ 下另有一份 glama.json，可能与根的不一致，需对齐）。
- **G2 ai.txt 自相矛盾**：同一文件里 (a) header "unique DOIs: 276,769" 与 GENETECH:CLAIMS 块 "带 DOI/PMID 的实体 271,099" 不一致；(b) "零引用域缺口 101/870" 与块内 "140/870" 不一致；(c) "MCP server 11 tools" 与实测 14 不一致。ai.txt 自称"机器可读、可独立复核"，但自身数字互相打架，破坏核心承诺。
- **G3 secret 泄漏**：README L184 明文承认 `ghp_/cfut_/虎皮椒/CORE_API_KEY` 历史泄漏，仅标 P2。这些令牌若仍有效，可被第三方盗用（API/部署/支付）。属真实安全隐患，不是文档问题。
- **G4 支付断头**：`license.swarmlabs.tools/health` 返回 ok/v2.0，但 `/api/hupijiao/order` 仍 404（部署版本落后）。修复代码已在 `unified-license/worker.js`（DEPLOY-NOW.md 步骤齐全），但上线需 `wrangler deploy` 浏览器 OAuth，**无法代跑**——这是账户门禁阻塞项，需用户手动。Pro 档（$29/月）全链路 demo 因此不可达。
- **G12 time-machine 未部署**：README 把"时间机器溯源"列为核心差异化，但 `snapshot_at` 工具依赖的 `data/time-machin/` 快照层"尚未部署 HTTP 端点，此处直读本地 JSON"——即差异化的数据层未建成，工具只能读本地现有 JSON，不能真正按日期回放。

### 3.3 工程与契约缺口（G10/G11）

- **G10 测试未验绿**：F2 地板已铺（5 测试文件 + 10 条 scripts），但本审计未执行 `npm test`，无 CI 绿证。round9 的核心论点是"没有东西自动阻止错误"——现在有了测试，但**是否真能拦住**需要跑一次确认。建议下一步第一件事就是 `npm test` 看全绿。
- **G11 schema 强制点待核**：`data/schemas/` 有 entity/citation-edges/knowledge-graph/station-tags 4 个 **JSON Schema** 文件（注意是 JSON Schema，非 round9 措辞的 zod；`package.json` 依赖 `zod ^4.6.7`，但 schemas 目录是 .json 而非 .ts，需确认是 JSON Schema 校验还是 zod 双轨）；`schema-validator.cjs` 被 4 条主管线 + MCP 入口接入，但 round9 要求的"ingest 出口 / sync-live 入口 / MCP 工具出口**三处强制**"是否全部生效，本扫描未逐点确认。若任一出口漏校验，缺字段实体仍可写入。

### 3.4 文档与可复现性缺口（G2/G13/G14）

- **G13 README 引用断链**：README L93-95 引用 `operations-plan/pipeline-oss-scan.js`（**MISSING**）、`pipeline-search-index.js`（EXISTS）、`pipeline-academic-datasets.js`（EXISTS）；L68 引用 `operations-plan/pipeline-domain-claim-guard.js`（EXISTS）；但 `build-knowledge-graph.mjs`（README L28 引用）**MISSING**。实际 operations-plan/ 顶层只有 `scheduler.js / scheduler-v2.js / overview.md / closed-loop-operations.md / cross-project-dashboard.md / state/ + reports/`，**没有 pipeline-* 主干脚本目录**。读者按 README 找不到对应脚本。
- **G14 DOI 三口径**：唯一 DOI 在 ai.txt(276,769) / README(271,099) / round9(256,086) 三处不同。README 自己立过规矩"任何对外数字必须写明由哪个脚本产出"，但这三个数字没有任何一处标注脚本来源，违反项目自身铁律。

### 3.5 安全与合规（G3/G8/G16）

- G8 非域混入 KG 也属合规面：对外声称"科学证据图谱"，图谱却含 tmp/docs 等目录节点，若被外部 agent 消费会产出"docs 与 tmp 相关"级垃圾候选。
