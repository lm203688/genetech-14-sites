**方法**：实测代码与线上服务 + 2026 最新技术/市场情报对标

## 摘要：五维总评分

| 维度 | 评分 | 一句话判断 |
|---|---|---|
| **全面性** | **B** | 30 域 29.4 万实体、7 数据源、DOI 100%；但全英文源、无中文库、无实体详情页、数据冻结 52 天 |
| **实用性** | **B-** | API/MCP/SDK 骨架真实可用；但检索 recall 0.44 未超 TF-IDF、无向量检索、单篇论文无法点开 |

| **互动性** | **B-** | 有真 AI 问答表单 + 交互知识图 + 14 MCP 工具 + A2A 卡；但无反馈/收藏/订阅/协作闭环 |

**综合：B-**。工程骨架已经"像一个产品"，但**对外可触达性（门户离线）、检索质量（不如 TF-IDF）、前沿合规（MCP 旧规范）**三处拖住了整体。

> ⚠️ 本次发现项目存在**"两个面孔"**：① 30 站知识引擎（API 在线，门户离线）；② `swarmlabs.tools` 在线虚拟实验室（GP 代理/不确定性量化/8 Bee Agents/157,836 实体，定位"可信 AI 科学的不确定性层"）。两者定位与数据口径不一致（29.4 万 vs 15.8 万实体），这是提升报告必须正视的第一问题。

## 一、全面性（B）：覆盖够宽，纵深与语言不够

### 实测证据
- **广度达标**：`/v1/domains` 实测返回 **30 站 / 294,330 实体**，中文标签齐全（智慧农业、AI Agent 生态、量子计算…）。
- **数据源 7 个**（agritech 样本）：crossref 5,871 / europepmc 1,388 / preprints 760 / pubmed 702 / datacite 673 / arxiv 80 / openalex 35 —— **全部为英文西文源**。
- **字段完整率**（agritech 1,000 条抽样）：doi 100%、publishedDate 100%、abstract 89.9%、tags 88.8%，但 **authors 仅 51.2%**；实体层**无 venue / citation 计数字段**。
- **实体详情页缺失**：`find _site -iname "*entity*"` 为空，每站只有 10 页分页列表（`page/1..10.html`），**用户无法点开单篇论文**。
- **数据冻结**：30 站 `lastUpdated` 全部停在 **2026-08-31 ~ 2026-09-01**，距今约 **52 天**。
- 历史遗留：KG 节点 60.2% 为 stub、DOI 覆盖 76%、abstract 全局空 30.89%、tags 空 35.30%。

### 缺口
1. **语言单一**：无 CNKI / 万方 / CSCD / 中文专利，`language` 字段全部 `unknown`（未填充）。
2. **纵深不足**：只有"题录+摘要"层，缺全文、图表、方法段、实验数据。
3. **可浏览性差**：无实体详情页，等于"有数据但读不到"。
4. **时效性差**：52 天未更新，与"活的知识引擎"承诺不符。

### 提升动作
- **A1** 补实体详情页（`build-entity-pages.mjs` 已规划未落地）：每篇一张 Data Card（题录/摘要/作者/引用/DOI 链接/相关实体）。
- **A2** 填充 `language` 字段 + 补 venue/citation 字段（可从 Crossref/OpenAlex 回填）。
- **A3** 接入中文源摘要级（CNKI/万方/维普），做中英双语对齐（详见 §三市场）。
- **A4** 解冻飞轮（见 P0-2）。

## 二、实用性（B-）：能调用，但"检索质量"和"可读性"不达标

### 实测证据
- **API 在线**：`/health` → `{"ok":true,"service":"genetech-api-guard"}`；`/v1/domains` 正常返回全量。
- **14 个 MCP 工具**已实装（list_sites/query_entities/get_entity/semantic_search/graph_search/ask/export_citation/submit_request/retrieve_requests/intake_health/citation_gaps/verify_entity/snapshot_at/domain_relatedness）。
- **双 SDK**（Python/TS）方法齐全：health/domains/registry/citation_edges/citation_gaps/entities/search_semantic/sample_pack/attribution。
- **30 站评测已跑**（`results-2026-10-18.json`）：300 query，**avgRecall@10=0.444**。
- **但**：TF-IDF 基线 **0.4545 > 引擎 0.444**；逐类型 `cross-entity` 0.092、`site-topic` 0.069、`tags-inverse` 0.127 —— **真实检索场景基本失效**，只有摘要字面匹配（0.974）能打。
- **无实体详情页** → 即便搜到，也无法阅读原文摘要的完整上下文。

### 缺口
1. **检索未超基线**：本质仍是 BM25/词典法，向量检索标 ❌（需 `GENETECH_EMBED_URL`）。
2. **语义/跨域检索弱**：cross-entity 0.09 意味着"找同一实体的不同表述"几乎做不到。
3. **可读性断头**：搜到结果 → 无法点开详情，实用性闭环缺最后一环。
4. **数据陈旧**：52 天冻结，用户查最新论文会失望。

### 提升动作
- **B1** 接入向量检索 + 混合重排（BM25+稠密+RRF+cross-encoder），目标 **recall@10 ≥ 0.60 且 > TF-IDF 10 个点**。
- **B2** 补实体详情页（同 A1，实用性与全面性共用）。
- **B3** 解冻飞轮 + 增量更新（同 A4）。
- **B4** 为 `semantic_search` 增加"按实体类型/年份/来源"过滤，提升真实任务命中。

## 三、使用性（C+）：设计完整，但门户"没上线"

### 实测证据
- **中文门户设计完整**：`_site/` 有 `index / search / ask / graph / insights / data / mcp / pricing / license / point-guide / blog`，导航全中文。
- **文档较厚**：`docs/` 共 **34 篇**，含 `consumer-onboarding.md`（含限流 60/min、429 Retry-After、错误码）、`ops-runbook.md`、`whitepaper.md`、`attribution.md`。
- **但门户未部署**：`lm203688.github.io` 返回 **"There isn't a GitHub Pages site here."**；`swarmlabs.tools` 是**另一个产品**（虚拟实验室），不是 30 站门户。
- **Onboarding 偏薄**：仅 4 段可复制代码；无 quickstart 教程、无 FAQ、无 notebook/示例。
- **逐站页英文 only**：`agritech/website/` 只有 Pagefind 静态搜索，无中文、无详情页。

### 缺口
1. **致命**：30 站门户**不可访问**——等于产品对外"不存在"。
2. 新手路径断：无"5 分钟跑通"教程、无示例 notebook、无 FAQ。
3. 逐站体验粗糙：只有搜索框，无筛选/排序/详情。
4. 文档与实现脱节：glama.json 仍写"14 站/5 工具"（历史遗留）。

### 提升动作
- **C1（最高优先）** 部署门户：Cloudflare Pages / GitHub Pages / Vercel 任一，绑定 `swarmlabs.tools` 子域（如 `engine.swarmlabs.tools`）。
- **C2** 写 `QUICKSTART.md` + 3 个可运行 notebook（搜索/图谱/引用导出），放首页。
- **C3** 逐站页中文化 + 详情页（同 A1）。
- **C4** 刷新 `glama.json` / `ai.txt` 口径（30 站 / 14 工具）。

## 四、互动性（B-）：有"问答"，缺"协作与闭环"

### 实测证据
- **真 AI 问答页**：`ask.html` 有 textarea + 提交 + 限流（免费层 20 次/分），经 `api-guard` 的 `/api/llm` 转发，不暴露上游。
- **交互知识图**：`graph.html` **262KB**，含嵌入式图谱数据，可交互。
- **14 MCP 工具 + A2A AgentCard**（`agent-ecosystem/agent-card.json` + 签名 + schema）——可被多智能体编排。
- **缺**：无用户账户、无收藏/订阅、无反馈按钮、无协作标注、无流式输出。

### 缺口
1. **无反馈闭环**：用户无法标记"答错/有用"，系统无法学习。
2. **无留存机制**：收藏夹、订阅（新论文提醒）、历史记录均无。
3. **无协作**：不支持团队共享查询/标注。
4. **无流式**：问答是整段返回，体验落后于 2026 主流。

### 提升动作
- **D1** 加"有用/没用/纠错"一键反馈，写入 `honesty-ledger` 闭环。
- **D2** 订阅：按领域/关键词/作者订阅新实体（复用 `submit_request` / `/v1/intel/subscriptions`）。
- **D3** 问答流式输出（SSE）+ 引用可点击到原文段落。
- **D4** 轻量账户（收藏/历史），或先做 localStorage 版降低门槛。

## 五、前沿性（B-）：骨架前沿，合规与"杀手锏"缺位

### 实测证据
- **已有**：MCP 14 工具、A2A AgentCard、DuckDB/Parquet（`data/parquet`，仅 neuromorphic 1 站）、identity-map（108MB）、claim 层、honesty-ledger、GraphRAG 模块（`mcp-server/src/graphrag.mjs`）。
- **MCP 合规缺口**：`index.mjs` 中 `outputSchema / ttlMs / stateless / server-discover` 命中 **0 次**；`http.mjs` 同时写 `2025-11-25` 与 `2026-07-28` 但**未实现无状态化**。而 2026-07-28 规范已**删除 initialize 握手、强制 `ttlMs`/`cacheScope`/`outputSchema`**。
- **检索前沿缺口**：无向量检索；2026 工程基线已是"混合检索 + 重排 + 上下文压缩"，纯 BM25 属落后。
- **最大机会未抓**：2026 年引文幻觉率 **4%–38%**、NSFC 2026 通告要求 AI 内容人工核实——**引用核验 API** 是当下最硬的护城河，项目有 `verify_entity` 但未做成独立产品。

### 缺口
1. MCP 未达最新无状态规范（agent 平台兼容性风险）。
2. 无向量/GraphRAG 实际启用（GraphRAG 模块存在但未接评测）。
3. 无独立"引用核验 API"（最强差异化未产品化）。
4. Parquet 仅 1 站，未铺开 30 站。

### 提升动作
- **E1** MCP 升级到 2026-07-28 无状态规范：`server/discover`、`ttlMs`/`cacheScope`、全量 `outputSchema`、读写工具分离。
- **E2** 启用向量检索 + GraphRAG（只在跨域桥接/路径查询用 GraphRAG，避免过度工程）。
- **E3** 把 `verify_entity` 升级为独立 **Citation Verification API**（输入 LLM 输出 → 逐条返回真伪+出处），这是可卖给期刊/基金/AI 写作工具的现金流产品。
- **E4** Parquet 铺开 30 站（DuckDB 查询加速 + 数据集发布）。

## 六、2026 技术与市场情报（决定提升方向）

| 领域 | 关键事实（2025–2026） | 对本项目的含义 |
|---|---|---|
| **MCP 生态** | 活跃服务器约 **15 万**，80% 只在单一注册表；2026-07-28 规范**全面无状态化**；AAIF（Linux 基金会）+ A2A v1.0 已成治理标准 | 必须无状态化 + 多注册表收录 + A2A 卡，否则 agent 平台不选你 |

| **交互期望** | NotebookLM 2026 可执行代码、导出 docx/pptx/xlsx；"摄取时编译"（LLM Wiki）兴起 | 门户应做**预编译综述页/实体页**，而非每次现场检索 |

## 七、市场定位：三层转向

1. **从"搜索引擎"→"证据基础设施"**：主打 claim-level 溯源 + **引用核验 API**，直接对冲 4–38% 引文幻觉。这是 2026 唯一能形成定价权的点。
2. **从"网站"→"可编排能力"**：MCP 无状态化 + 官方/多注册表 + A2A AgentCard，成为 Gemini/Claude Science/玻尔的**底层数据源**而非竞品。
3. **从"英文覆盖"→"中英双语 + 私有化"**：吃"人工智能+"与北京 AI4S 预算，做 CNKI/万方做不到的跨库对齐与内网 MCP 部署。

### 血泪教训（本轮新增）

1. **SDK v2.3.1 的 `outputSchema` 触发严格 `structuredContent` 校验**——14 工具从 `content[{text}]` 迁移需逐个改造，本轮保留 outputSchema 省略 + 走 `_meta.cacheHint` 透传，SDK 未来升级再回来接。
2. **`_site/` 是构建产物被 gitignore**——反馈按钮若直接改 `_site/ask.html` 会被提交工具拦下；改 `tools/build-site.mjs` 生成器是唯一入库路径。
3. **CF 经典 SW 不能 ESM import 共享模块**——`lib/citation-verify.mjs` 是 Node 侧同源真源，worker 内联同步副本，两处需人工保持一致。
4. **`_site/assets/ask.js` 有 pre-existing 语法 bug**——`replace(//+$/, '')` 正则未转义（应为 `/\/+$/`），整个 IIFE 抛 SyntaxError 导致前端 JS 无法加载。反馈闭环若不修此 bug 永远跑不起来。
