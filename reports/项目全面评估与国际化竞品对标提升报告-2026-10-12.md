## 0. 执行摘要

### 0.1 一句话结论

> **这是一套"工程完成度中上（≈60%）、科学先进性明显滞后（≈35%）、国际化定位清晰但尚未占位（≈40%）"的系统。**
> 它最值钱的东西——"可验证性"——目前只是**元数据层的可验证**（DOI/来源/时间齐全），还不是**知识层的可验证**（实体归一、引用立场、证据抽取都没有真实产出）。
> 与国际同类的差距**不在工程量，而在"加工层用的方法落后 1–2 代"**：ER 用 Jaccard+编辑距离（对手用概率链接 + LLM），引用立场用词典打分（对手 Scite 用模型分类 16 亿条引用陈述），检索用 BM25+RRF（对手用 GraphRAG + 向量混合）。
> **结论**：方向对、地基稳、故事好，但**塔尖是空的，且塔尖才是国际竞争的战场**。

### 2.4 加工层方法实况（本轮重点：看"方法"而非"有无"）

> 10-11 报告说"ER/stance 已从 0 到有"。本轮进一步核实**用什么方法做的**——这决定"科学先进性"得分。

| 组件 | 实现方法（代码事实） | 2026 国际 SOTA | 代差 |
|---|---|---|---|
| **实体解析 ER** | `pipeline-entity-resolution.js`：**Jaccard≥0.7 且 Levenshtein 比率≥0.8 → union-find 聚类**（首字符分桶）。文件头明确**拒绝 Splink**（因 pyarrow 28.5MB 下载超时） | Splink（Fellegi-Sunter 概率链接）+ LLM-ER（"Resolving the Canon" 2026；ACM DL 深度学习 ER 综述 2026） | **落后 1–2 代** |
| **引用立场** | `pipeline-stance-analysis.js`：**词典打分**（`W_POS=1.0, W_NEG=1.15, W_UNC=0.4`，阈值 ±0.15） | Scite 模型分类（Supporting/Contrasting/Mentioning，16 亿条）；DSPy LLM 分类（cic-llmprompt 2026）；SciCite/ACL-ARC 基准 | **落后 2 代** |
| **检索** | `search.mjs`：**BM25（k1=1.5,b=0.75）+ 字段加权 + RRF(K=60)**，向量仅 env-gated 可选 | GraphRAG + Agentic RAG + 向量混合 + cross-encoder 重排（4 段式） | **落后 1 代** |
| **图检索** | `graphrag.mjs`：沿 4 类边 **BFS 多跳** | GraphRAG 社区摘要 + 全局/局部查询；HGNet 科学 KG 生成（ICLR 2026） | **落后 1 代** |
| **溯源/可验证** | provenance 字段（DOI/URL/来源/时间/confidence） | W3C PROV-O / RO-Crate / 内容寻址 | **概念接近前沿**（唯一亮点） |
| **缺口发现** | 引用边 → 870 站对矩阵 → 零引用对 | Swanson LBD + LLM+KG 假设生成（LBD 综述 2026） | **落后 1 代（方向对）** |
| **治理/护栏** | 5 条 JSON-logic 策略 + CI 双向回归 | OPA/Rego 同分工 | **工程成熟（非科学）** |

> **这张表是本报告最重要的表**：它说明项目的"加工层"虽然"从 0 到有"，但**用的是经典算法与词典**，而国际对手已经用**概率模型、LLM、向量混合、图增强**。**"有功能"≠"有先进性"。**

## 4. 国际化定位（本轮核心新增）

### 4.1 全球科研知识基础设施的四层结构

```
┌─────────────────────────────────────────────────────────┐
│  应用层（B2C/B2B 产品）  Elicit · Consensus · SciSpace ·  │
│                          Undermind · ResearchRabbit       │
├─────────────────────────────────────────────────────────┤
│  加工/增值层（"如何引用/证据/缺口"）  Scite(立场) ·       │
│                          Dimensions(多源) · 本项目(定位) │
├─────────────────────────────────────────────────────────┤
│  元数据底座（免费开放）  OpenAlex · Crossref · PubMed ·   │
│                          Semantic Scholar · DataCite      │
├─────────────────────────────────────────────────────────┤
│  分发协议层  MCP · REST API · TAXII/STIX                  │
└─────────────────────────────────────────────────────────┘
```

**项目当前实际站位**：**底座层（自建 30 域 29 万实体）+ 分发层（MCP/API，未发布）**。
**项目自我宣称站位**：**加工层（可验证证据图谱）**。
**差距**：**宣称在加工层，实际停在底座层**——这就是国际定位的核心问题。

### 4.2 定位象限（2026 国际坐标）

```
            高"加工深度"
                 │
   Scite ●       │       ● 本项目(目标位)
   (立场,付费)   │       ○ 本项目(实际位)
                 │
 低"开放性"──────┼──────高"开放性"
                 │
   Elicit ●      │       ● OpenAlex / S2
   (应用,付费)   │       (底座,免费)
                 │
            低"加工深度"
```

**结论**：**"高加工深度 × 高开放性"象限目前是真空**——Scite 加工深但封闭付费，OpenAlex 开放但只到元数据。**这正是项目的战略生态位。但真空 ≠ 已占位**：项目尚未把"加工深度"做出来（ER/立场/向量为空），所以仍停在右下角。

### 4.3 中国 vs 国际：项目的位置

| 维度 | 国际同类 | 本项目 | 差距 |
|---|---|---|---|
| 数据规模 | OpenAlex 5 亿 / S2 2.14 亿 | 29.4 万（≈它们的 0.06%） | 数据量必输，**不应比数据量** |
| 开放程度 | OpenAlex/S2 免费 | 免费 + 可溯源（更强） | **可溯源是差异化** |
| 机器原生 | 多数仅 REST | MCP + REST（双通道） | 方向领先，**未发布** |
| 加工深度 | Scite 立场 / Dimensions 多源 | ER/立场/向量均弱 | **落后 1–2 代** |

## 6. 技术壁垒与技术深度（深挖）

### 6.1 六层壁垒模型（本轮细化）

```
第 5 层  生态/标准话语权   ← schema/评测成为行业基准（终极，最难被超越）
第 4 层  合规/授权壁垒     ← 独家数据授权、牌照、法务护城河
第 3 层  数据飞轮壁垒      ← 用的人越多→缺口越准→越多人用（正反馈）
第 2 层  算法/加工壁垒     ← ER/立场/向量/证据抽取（别人复现不出同等效果）
第 1 层  切换成本壁垒      ← 客户深度集成，迁移代价高
第 0 层  流程/工程壁垒     ← 护栏/审计/编排（可复刻，是地基不是壁垒）
──────────────────────────────────────────────
```

### 6.2 逐层打分（项目现状）

| 层 | 壁垒类型 | 项目现状 | 得分 | 证据 |
|---|---|---:|---:|---|
| 0 | 流程/工程 | ✅ 扎实 | 75 | 5 策略 + 双向回归 + 编排 + 审计 |
| 1 | 切换成本 | ❌ 无 | 15 | API 可替换，无客户集成 |
| 2 | **算法/加工** | ❌ 弱 | **25** | ER=Jaccard、立场=词典、检索=BM25 |
| 3 | **数据飞轮** | 🟡 有设想未转 | **30** | 飞轮冻结 41 天；缺口矩阵薄 |
| 4 | 合规/授权 | ❌ 无 | 15 | 无独家授权，再分发授权未定 |
| 5 | 生态/标准 | ❌ 仅雏形 | **20** | 148 条评测集是唯一起点 |

**判读**：**项目在第 0 层（流程）做到 75 分，第 2–5 层（真壁垒）全部低于 30 分。** 这印证了 10-10 报告的判断：**当前是"流程壁垒"，不是"技术壁垒"**。流程壁垒**必要但不充分**——它让系统"不出错"，但不能让系统"不可替代"。

### 6.3 三个"可挖深"的真壁垒方向（本轮结论）

> 壁垒不是"更多护栏"堆出来的，而是**在别人做不出的地方做深**。项目有三个方向**既有基础、又能形成代差**：

#### 方向一：**可验证证据图谱（Verifiable Evidence Graph）** ← 唯一已接近前沿的
- **为什么是壁垒**：国际对手要么封闭（Scite）、要么只到元数据（OpenAlex）。**"每条带 DOI + 来源 + 时间 + confidence + 可独立复核"** 是稀缺的；一旦把"可验证"从元数据级做到**知识级**（实体归一 + 立场 + 证据 span 都带 provenance），就形成"**别人要么没有、要么不愿开放**"的差异化。
- **挖深路径**：ER 产出 identity graph（带 match_confidence + 逐条 provenance）→ 立场产出带 span 的三分类 → 证据抽取带 claim/method 定位 → 全部挂 W3C PROV-O。
- **验收**：任一实体可"3 秒看懂可信度"；任一分歧可被第三方引着 provenance 复核。

#### 方向二：**跨域空白发现（Cross-Domain Gap Discovery）** ← 最具原创性
- **为什么是壁垒**：**OpenAlex/Scite 都不做"跨域空白"**；这是"科学学（Science of Science）"的应用，方向对（Swanson LBD 至今仍是活跃领域，2026 有 LLM+KG 新方法）。
- **现状**：引用网络 25,682 边（13× 扩展），但**种子仅 1,634** → 结论"薄"。**缺口矩阵 140/870 里，很大比例是"我们没抓到"而非"没人研究"**。
- **挖深路径**：引用网络扩容（种子 → ≥20,000，边 → ≥50,000）→ 引入 LLM+KG 假设生成（对标 Co-Scientist 的方法，但输出"可复核的证据链"）→ 用领域专家抽检建立可信度。
- **验收**：扩网后重出《跨域研究空白报告》，**领域专家抽检通过**（而非自评）。

#### 方向三：**机器原生 + 标准话语权（Agent-Native Standard）** ← 最低成本的高杠杆
- **为什么是壁垒**：MCP 2026 已有 **10,000+ server**，但**"可验证科研数据"的 MCP 供给仍是真空**；谁先定义"可验证科学证据"的 schema/评测，谁就拿到标准话语权。
- **现状**：14 工具已就绪但**未发布**；148 条评测集是雏形。
- **挖深路径**：MCP 迁 v2 + 发布 + remote → 开源加工引擎（ER/立场/检索/评测代码）→ 把"可验证科学证据"schema 与评测提交为社区标准 → 公开 leaderboard。
- **验收**：`npx @genetech/data-mcp` 可用；公开可复现的评测页；≥1 个社区标准提案。

### 6.4 壁垒对比：项目 vs 国际对手

| 壁垒层 | Scite | OpenAlex | Co-Scientist | **本项目** |
|---|---|---|---|---|
| 流程/工程 | 中 | 中 | 中 | **强** |
| 算法/加工 | **强**（立场） | 弱 | **强**（假设） | 弱 |
| 数据飞轮 | 中 | **强**（规模） | 中 | 弱 |
| 合规/授权 | 中 | 弱 | 弱 | 弱 |
| 生态/标准 | 中（MCP） | **强**（事实标准） | 弱 | 弱（雏形） |
| **可验证性** | 弱 | 中 | 弱 | **强（唯一）** |

**结论**：项目**唯一确定的壁垒是"可验证性"**。**必须把资源全部押在这一个点上做深**，而不是平均用力铺 30 域。
