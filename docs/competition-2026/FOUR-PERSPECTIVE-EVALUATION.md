| 项 | 评分 | 事实依据 |

## 三、自动化迭代提升策略

### 策略 1：数据飞轮自愈（最高优先级，1 天）

**问题**：管线停摆 21 天，21/22 站数据已旧。根因是 backfill engine 依赖的环境变量/网络间歇性故障，看门狗只告警不修复。

**方案**：
```
┌─────────────┐     ┌────────────────┐     ┌──────────────┐
│ WatchDog     │ ──→ │ Repair Agent    │ ──→ │ Backfill      │
│ 发现漂移      │     │ 1. 重试数据源    │     │ Engine v2    │
│ (当前)        │     │ 2. fallback 源  │     │ 增量补数据    │
└─────────────┘     │ 3. 降级发布     │     └──────────────┘
                    └────────────────┘
                           │
                           ▼
                    ┌────────────────┐
                    │ Stuck Agent    │
                    │ 连续 3 次失败   │
                    │ → 建 GitHub    │
                    │   Issue + 通知 │
                    └────────────────┘
```

**具体代码改造**（`operations-plan/closed-loop-engine.js` 已有骨架，需补）：
1. 加熔断器（`tools/circuit-breaker.mjs` ✅ 已提供）
2. 加数据质量前置校验（`tools/data-quality.mjs` ✅ 已提供）
3. 加自愈重试逻辑（3 次间隔重试 + fallback 源切换）
4. CI 加 `daily-health-check` workflow，每日 06:00 跑

### 策略 2：多 Agent 架构显式化（2 周）

**问题**：Agent 是隐式函数调用，评审人看代码是「一个大脚本」不是「多 Agent 协作」。

**方案**：DAG + 事件总线双轨制

```
┌─ Agent Registry ──────────────────────────────────────────┐
│ 6 个 Agent，每个声明 role / tools / decision / fs_scope    │
└──────────────────────┬────────────────────────────────────┘
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
  Collector       Normalizer       Validator
  (parallel)      (parallel)       (serial)
        │              │              │
        └──────────────┼──────────────┘
                       ▼
  ┌────────────────────────────────────────┐
  │  DAG Runner                            │
  │  fetch → normalize → validate → enrich │
  │     → publish                          │
  │  每个 node 声明 deps，零手动编排         │
  └────────────────────────────────────────┘
                       │
                       ▼
  ┌─ Event Bus ─────────────────────────────┐
  │ data/events/queue.jsonl                │
  │  Agent 间通过事件解耦                    │
  │  死信队列保证零丢失                      │
  └────────────────────────────────────────┘
```

**具体产出**：
- `tools/dag-runner.mjs` ✅ 已在 ENGINEERING-MECHANISMS.md 中提供
- `data/events/queue.jsonl` + producer/consumer 约定
- `operations-plan/agent-registry.json`（声明 6 个 Agent）

### 策略 3：Guard 矩阵真生效（1 周）

**问题**：Guard 是命名约定，无策略引擎。评审问「Guard 是真的吗」答不上。

**方案**：Policy-as-code + 默认拒绝

```
┌─ Agent 动作 ──────────────────────────────┐
│ {action:"publish", target:"swarmlabs",     │
│  count:421, guards_passed:[...]}           │
└──────────────────┬────────────────────────┘
                   ▼
┌─ Guard Eval (JSON-logic) ─────────────────┐
│ 读 guards/publish.policy.json              │
│ default: deny                              │
│ 匹配规则 → allow / deny + reason           │
└──────────────────┬────────────────────────┘
                   ▼
           ┌──────┴──────┐
           ▼             ▼
        allow          deny
           │             │
           ▼             ▼
        执行       Fallback Ladder:
                   retry → degrade → escalate → hardfail(log)
```

**具体产出**：
- `guards/publish.policy.json` / `ingest.policy.json` / `evolve.policy.json`
- `tools/guard-eval.mjs`（JSON-logic 求值器，零依赖）
- 在 backfill-engine / build-site 的 publish 前插入 guard eval

### 策略 4：数据质量前置校验（1 天）

**问题**：漂移写入后才被 WatchDog 发现，事后修复成本高。

**方案**：`tools/data-quality.mjs` 已在 ENGINEERING-MECHANISMS.md 中提供，9 条校验规则：

| 规则 | 阈值 | 违反时 |
|------|------|--------|
| entity_count | 10–5000 | 批次拒绝 |
| title_non_null_rate | ≥100% | 批次拒绝 |
| id_unique | 100% 唯一 | 批次拒绝 |
| domain_valid | 允许列表 | 过滤 |
| abstract_rate | ≥40% | warn |
| author_count | 1–200 | 过滤 |
| provenance_rate | ≥80% | warn |
| title_length | 5–500 | 过滤 |
| no_empty_entities | 100% | 批次拒绝 |

在 backfill-engine publish 前插入：
```js
const quality = await check(readyEntities, expectations);
if (!quality.pass) throw new Error(`data quality failed: ${quality.failures.length} rules`);
```

## 五、核心结论

**一句话**：14 站有数据（49,879 × 22 领域）和工程（6 源管线 + MCP + 支付），但「Agent 是隐式的」「Guard 是命名的」「数据是停摆的」「商业模式是空的」——这 4 件事不解决，无论评审视角还是投资人视角，都过不了。

**最高 ROI 动作**：先让数据飞轮活过来（熔断 + 质量校验 + 自愈），这是所有视角的第一个扣分项，修复后总分从 2.9 提到 3.3+。
